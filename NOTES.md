# Livery preview processing notes

The four supplied JPGs are photographs of the wrapped car from four angles. The `corpus1` shell receives a procedural world-Z body coat: ivory white at the nose, transitioning through the middle to saturated blue before the tail. The baked RGBA images in `assets/livery/processed/` carry the printed artwork at full strength; side masks include the window band and continue to exclude lamps, plates, tyres, the rocker, and the studio background. The runtime makes one shared side projector volume, then builds a `DecalGeometry` for the painted shell (`corpus1`) and each glazing mesh (`glass2`, `Black_glass1`) from that same frame. All targets sample the same calibrated source-camera coordinates, so strokes stay aligned across the door and window seams. Side glazing uses an opaque dark tint beneath the artwork. Hood and rear retain their own source-camera projections and structural cutouts. `assets/livery/parts.json` records spatial panel intervals, model face/vertex ranges, wheel centers, photo landmarks, and structural exclusions.

The gradient uses `smoothstep` from body Z `+1.2456 m` (white) to `-0.9613 m` (fully blue), based on the `corpus1` extent `[-2.4326, +2.4717] m`. Its linear RGB endpoints are `(1.000, 0.995, 0.975)` and `(0.015, 0.430, 0.860)`. The end values apply to every point at or beyond those transition limits, including the full tail.

Side projection scale uses the 2.90 m Taycan wheelbase. Hood and rear images are end-on and do not show wheel arches; those views use lamp/body-width registration. Artwork is still extracted from photographs, so some source perspective and local shading remain in the artwork pixels. Rebuild baked images, camera metadata, and the panel map with `uv run --with opencv-python --with numpy --with trimesh python utils/process_livery.py`; render a part-color diagnostic with `uv run --with opencv-python --with numpy --with trimesh python utils/render_part_map.py`.
